**You have to govern AI agents and the program is young.** Pick the stage that matches you. Each one gives you three actions.

## You have not started

1. **List your agents.** For each one, record the owner, the tools it can call, the data it can reach and what it can change. [Week 1 shows how](/docs/overview/first-30-days).
2. **Find out which rules apply to you.** Start with the EU AI Act if you operate in the EU, then your sector regulator.
3. **Put a floor in place.** Limit what each agent can do, give each agent its own identity, and log what it does. [First 30 Days](/docs/overview/first-30-days) is a four-week plan.

## You are piecing things together

1. **Name an owner for each question in the table below.** A question with no owner is a gap.
2. **Add an independent check on agent output** before anyone relies on it. See the [Validation Pipeline](/docs/overview/composition-patterns).
3. **Add an approval step for actions that cannot be undone.** See the [Governed Decision Flow](/docs/overview/composition-patterns).

## You have a program

1. **Check your versions and dates.** Several sources changed in 2026. The [Source Guide](/docs/reference/source-guide) has the current ones.
2. **Trace one real decision end to end.** The [Reference Walkthrough](/docs/overview/reference-walkthrough) shows what to look for.
3. **Test your program against the gaps.** See [where the sources say little](/docs/reference/source-guide#where-the-sources-say-little).

## Which source answers which question

No single source covers agent governance. Use this table to find the right one.

| Your question | Go to |
|---|---|

| How do I threat-model my own agent system? | [CSA MAESTRO](https://cloudsecurityalliance.org/artifacts/maestro-v2) |
