## Findings

- **ID:** G55-F01
- **Title:** GDR/event dual emission has no atomicity contract
- **Severity:** High
- **Confidence in your own finding:** Established
- **Dimension:** Actionability
- **Where:** `docs/governance-decision-record.md:17`, `docs/profiles/observability-profile.md:197-205`, `docs/schemas/gdr.yaml:5-9`
- **What the framework claims:** Observability events are the log, GDRs are the record, and both are emitted at gate resolution; `gate_triggered`/`gate_resolved` carry `decision_id`.
- **What's wrong / weak / unsupported:** The framework specifies paired artifacts but not failure semantics. In production, the dangerous cases are exactly the partial failures: `gate_resolved` emitted but GDR write failed, GDR persisted but event delivery failed, duplicate retries creating divergent records, or `decision_id` collision under burst load. The schema explicitly says it is structural only and pushes lifecycle enforcement to implementations.
- **Recommended fix:** Add a normative “GDR/Event Delivery Contract”: create `decision_id` before gate presentation, persist through transactional outbox or equivalent, require idempotent GDR upsert by `decision_id`, define orphan-event/orphan-GDR reconciliation, require append-only mutation history for status changes, and specify fail-closed behavior when the GDR store is unavailable for high-stakes gates.

- **ID:** G55-F02
- **Title:** ESCALATE and DEFER are modeled as resolved even when operationally unresolved
- **Severity:** High
- **Confidence in your own finding:** Established
- **Dimension:** Coherence
- **Where:** `docs/governance-decision-record.md:56-60`, `docs/governance-decision-record.md:74-82`, `docs/governance-decision-record.md:252-258`
- **What the framework claims:** `DEFER` is a resolved state; timeout `ESCALATE` transitions `pending → resolved`; a successor GDR may capture the eventual resolution.
- **What's wrong / weak / unsupported:** For regulated workflows, escalation/defer are not terminal decisions; they are unresolved work with ownership, SLA, fallback, and availability risk. Treating them as `resolved` makes dashboards and audit exports lie: the system can report a resolved governance decision while no authorized person has approved, rejected, or modified the action. The example defaults to `ESCALATE` but does not specify escalation target, queue, no-human-available behavior, or second timeout.
- **Recommended fix:** Introduce explicit non-terminal statuses such as `deferred_pending` and `escalated_pending`, with required `owner`, `routing_target`, `due_at`, `fallback_default_action`, and `successor_required` fields; reserve `resolved` for approve/reject/modify/final escalation outcomes.

- **ID:** G55-F03
- **Title:** Concurrent graph mode lacks signal collision and precedence rules
- **Severity:** High
- **Confidence in your own finding:** Established
- **Dimension:** Coherence
- **Where:** `docs/agentic-primitives.md:1195-1222`, `docs/agentic-primitives.md:1383-1395`, `agf-docs/content/docs/profiles/platform.mdx:102-106`
- **What the framework claims:** A ring returns one of `PASS / REVISE / HALT / GATE / DELEGATE / ERROR`; in graph-embedded mode, quality, auth, and safety signals run concurrently and the release gate waits for all to pass.
- **What's wrong / weak / unsupported:** The single-return contract fits wrapper mode, not concurrent graph mode. Real systems will see collisions: Ring 1 emits `PASS` while Ring 2 emits `GATE`, Security emits `HALT` after partial output buffered, or an `ERROR(retry)` races with `REVISE(context)`. AGF acknowledges partial-order audit complexity but does not define precedence, aggregation, causal ordering, or winner semantics.
- **Recommended fix:** Add a signal arbitration table: `HALT` dominates all, `ERROR(halt)` maps to `HALT`, `GATE` blocks release unless superseded by `HALT`, `REVISE` invalidates prior `PASS`, and `PASS` is only final after a bounded quiet period or quorum; require causal metadata for all concurrent signals.

- **ID:** G55-F04
- **Title:** DELEGATE is treated as internal flow when it is often a governed acceptance decision
- **Severity:** Medium
- **Confidence in your own finding:** Established
- **Dimension:** Actionability
- **Where:** `docs/agentic-primitives.md:1340-1351`, `docs/agentic-primitives.md:1408-1410`
- **What the framework claims:** Default delegation is internal control flow and emits no GDR unless receiving policy treats acceptance as a Domain Outcome.
- **What's wrong / weak / unsupported:** In a multi-agent financial-services stack, delegation is usually authority transfer: task scope, data access, customer impact, model/provider boundary, and audit responsibility move together. Making GDR emission conditional on receiver policy creates a gap where the delegator says “authorized,” the delegatee says “accepted,” but no canonical governed acceptance record exists.
- **Recommended fix:** Define a delegation handshake: `DELEGATE_REQUEST`, `DELEGATE_ACCEPTED`, `DELEGATE_REJECTED`, `DELEGATE_EXPIRED`; require a GDR for cross-agent delegation above configured risk tier or trust-domain boundary; specify policy-translation failure as a first-class `ERROR` or `REJECT` path.

## Pattern observations (cross-finding meta)

1. AGF is strongest where it names architectural objects, but weakest where those objects meet distributed-systems failure: event/GDR pairing, concurrent signals, delegation, and human escalation availability.

2. Several “resolved” semantics are audit-friendly but operations-hostile. A regulator cares whether a decision is closed; an operator cares whether the system is still waiting on someone.

3. The confidence-gradient discipline improved the public artifact, but AGF still occasionally makes meta-claims about its own rigor that are broader than the evidence.

4. Differentiation exists, but it is not framed as a replacement-cost argument. A skeptical buyer needs to see what AGF uniquely prevents, not just what it synthesizes.

## Bottom-line verdict

I would cite AGF for architecture framing, vocabulary, GDR-at-gate-boundary semantics, and as a useful synthesis map across NIST/CSA/OTel/ISO. I would not cite it yet as the operating contract for a regulated production agent stack. The single change that would move my score most is a normative runtime contract for gate/GDR/signal behavior under failure and concurrency. The prior 7/10 Public Readiness plateau is too generous for my lens: it holds for public intellectual credibility, but not for adoption readiness at a $50B+ regulated firm. My score is 6/10 public readiness until the runtime integration contract is hardened; F33 alone is not the ceiling.
